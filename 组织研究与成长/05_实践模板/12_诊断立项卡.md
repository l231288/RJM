# 诊断立项卡

> [!warning] 空白模板
> 复制后填写。立项卡先约定要解决的业务问题和决策用途，不预设一定要调组织图、考核或编制。

## 为什么诊断

- 触发事件或结果缺口：
- 结果使用者/客户：
- 现有目标及其来源、版本、期限：
- 本次诊断要支持的具体决策：
- 若不诊断，可能造成的影响：

## 范围与条件

- 诊断单位与工作链编号：
- 覆盖的地区、团队、岗位、业务阶段：
- 不在范围内的事项：
- 必须遵守的政策、内控、预算和时间约束：
- 诊断负责人、业务负责人、批准者、参与者：
- 可能受方案影响的人；如何听到他们的声音：

| 资料 | 期间/口径 | 提供者 | 质量和缺口 | 使用与保密要求 |

| 成功/延期/异常事项 |  |  |  |  |
| 审批、交接、工时或系统记录 |  |  |  |  |
| 不同角色访谈 |  |  |  |  |

## 开始前的判断

- 问题是否已足够具体，可追踪一条真实工作链：
- 是否需要完整诊断，还是先处理明显且低风险的流程故障：
- 现阶段最大的证据缺口：
- 第一轮交付物和复核日期：
- 什么情况需要缩小、暂停或重定诊断范围：
