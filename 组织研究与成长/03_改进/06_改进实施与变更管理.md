# 改进实施与变更管理

## 从建议走到实际运行

1. 明确改进范围、批准者、执行负责人、受影响岗位及预期结果。
2. 画出改进前后的事项路径：谁接收、谁决定、谁交付、异常谁处理。
3. 与实际执行者核对新路径是否可行，提前准备系统、数据、培训和权限。
4. 小范围试运行，记录偏离设计的事项及原因。
5. 根据试运行调整，再决定扩大、暂缓或回退。
6. 把新规则写入日常工作安排，并指定后续维护者。

## 行动记录必须同时写

| 字段 | 要求 |
| --- | --- |
| 工作链和根因 | 能追溯到 [[08_组织诊断案例模板]] |
| 改进动作 | 描述实际改变的行为或交接 |
| 负责人和期限 | 明确有权推动的人与时间 |
| 前提与依赖 | 系统、预算、跨部门决定、培训 |
| 实施信号 | 新流程是否真的被执行 |
| 结果信号 | 交付是否改善 |
| 负面信号 | 成本、质量、风险和人员负担是否恶化 |
| 调整条件 | 什么情况回退或改方案 |

不能把“发了通知”当作实施成功。需用真实事项检查执行偏差，并在复评中区分方案没执行、方案执行了但机制判断错误、方案有效但外部环境改变。

复评方法见 [[07_组织匹配复评]]，空白记录见 [[09_改进行动与复评模板]]。
